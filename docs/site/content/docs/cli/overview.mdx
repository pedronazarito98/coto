The Coto CLI is the `coto` command-line interface for scripting a running Coto editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control Coto-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → Coto CLI](/docs/settings). On Linux the command is `orca-ide`, because GNOME Coto's screen reader already owns `/usr/bin/orca` — see [Install → Linux](/docs/install#linux).

Agents can install the matching Coto CLI skill with:

```bash
npx skills add https://github.com/pedronazarito98/coto --skill orca-cli
# headless / no Settings UI:
coto skills install --skill orca-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable Coto skill, including `coto skills install` / `coto skills update`.

## Install & verify

```
command -v orca
coto status --json
```

## Worktree commands

```
coto worktree ps --json
coto worktree create --repo id:<repoId> --name my-task --issue 123 --json
coto worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
coto worktree current --json
coto worktree set --worktree active --comment "reproduced bug" --json
coto worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
coto worktree set --worktree active --pr null --json
coto worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [Coto CLI reference](/docs/cli/reference).

## Terminal commands

```
coto terminal list --json
coto terminal read --json
coto terminal send --text "npm test" --enter --json
coto terminal wait --for tui-idle --timeout-ms 30000 --json
coto terminal create --worktree path:/projects/app --command "npm test" --json
coto terminal split --direction vertical --command "npm run dev" --json
```

`terminal send` is for shells, dev servers and REPLs. To message another agent, use `coto orchestration send`; for tracked multi-agent work, use [Orchestration](/docs/cli/orchestration).

## File commands

Open files and diffs as tabs in their Coto worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
coto file open src/App.tsx
coto file diff src/App.tsx --staged
coto file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `coto tab profile`; start with `coto tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `coto automations` to create, inspect, run, and remove scheduled Coto tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in Coto account (`coto artifacts share|update|list|delete`). Publishing follows **Settings → Artifacts → Allow publishing public artifact links**: on by default for new profiles, while profiles created before this default keep their previous setting. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
coto goto --url https://example.com --json
coto snapshot --json     # returns refs like @e1, @e3
coto click --element @e3 --json
coto fill --element @e1 --value "user@example.com" --json
coto screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
orca set device --name "iPhone 12" --json
coto screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through Coto's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator, list the worktree's attached devices with `coto emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving Coto.

```
coto emulator list --json
coto emulator attach "<device-name-or-udid>" --json
coto emulator tap 0.5 0.7 --json
coto emulator type "hello" --json
coto emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
coto emulator rotate landscape_left --json
coto emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
